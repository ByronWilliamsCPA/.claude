## TL;DR

**The fleet is cutover-ready with zero remediation work required.** v43.150.0 accepts every single one of the 34 active per-repo `renovate.json` files and the homelab global `config.json`. The Phase 2 cutover collapses from "audit + remediate + deploy" to just "deploy."

| Question the plan asked | Answer |
|---|---|
| Will any per-repo config be rejected by v43? | **No.** 0 hard failures across 34 repos. |
| Will the global config be rejected by v43? | **No.** Validates clean. |
| How many repos need pre-cutover fix PRs? | **0.** |
| Recommended target version | `renovate@43.150.0` (npm latest 2026-05-24) |
| Cutover diff size | ~3 lines (docker-compose image pin, optional systemd ExecStartPre removal) |

## Methodology

- **Target version:** `renovate@43.150.0` from the npm registry. Note: `endoflife.date/renovate` reports `43.195.1` as latest, but that version is NOT published to npm. npm is the authoritative source for what `npx --package renovate@X` can actually install, so 43.150.0 is the correct cutover target.
- **Validator:** `renovate-config-validator` from the `renovate@43.150.0` npm package, installed once at `/tmp/v43-audit/node_modules/.bin/renovate-config-validator`.
- **Fetch:** `gh api repos/{org}/{repo}/contents/renovate.json` (per `feedback_gh_search_code_staleness.md`, never `gh search code`).
- **Repos audited:** 18 BWCPA + 25 williaby = 43 active (non-archived), minus 2 RENOVATE_IGNORED exempt repos (`dart-frog-paludarium`, `homelab-agent-configs`) = 41 in scope. 34 of those had a `renovate.json` to validate; 6 had none (separate CI-020 gap); 1 was the org template.
- **Logs:** `/tmp/v43-audit/{org}__{repo}.log`. `/tmp/v43-audit/results.tsv` for the summary table.

## Phase 1.A: Target version and digest

- **npm-canonical latest v43.x:** `43.150.0`
- **Docker image digest:** to be resolved on the homelab server itself at cutover (Day 8) since this audit environment cannot reach the Docker registry. Command for that step: `docker pull renovate/renovate:43.150.0 && docker inspect renovate/renovate:43.150.0 --format '{{index .RepoDigests 0}}'`.
- **Renovate release cadence is daily.** Re-resolve npm latest at cutover; if a newer 43.x has shipped between this audit and Day 8, target that and re-validate the global config against it (per-repo configs are already known to pass on 43.150.0+).

## Phase 1.B: Global config v43 compatibility

Tested `homelab-infra/services/renovate/config/config.json` (origin/main snapshot at audit time) against the v43.150.0 validator.

| Risk check | Status |
|---|---|
| `postUpgradeTasks` shell-mode default change | **SAFE.** Only one command in the block: a harmless `echo`. No shell metacharacters, no fork to sub-shell. v43 default shell-mode-off does not break it. |
| `lockFileMaintenance` grouping change | **SAFE.** `lockFileMaintenance` is a top-level block, NOT inside any packageRule. The v43.0.0 grouping breakage (reverted in 43.20.1) was specifically about packageRule grouping; our config doesn't use that. |
| `replacements` grouping change | **SAFE.** Zero `replacements` references in any packageRule. |
| `fileMatch` vs `managerFilePatterns` | **AUTO-MIGRATED.** The 3 `fileMatch` entries in `customManagers` (lines 293, 302, 310) are auto-recognized by v43 as the legacy form. Optional cleanup post-cutover; not required. |
| `matchSeverity` placement change | **N/A.** Not used in the global config. |
| `prPriority` placement | **N/A.** Not used at the wrong level in the global config. |

**Validator verdict:** `INFO: Config validated successfully` with one `WARN: Config migration necessary` notice. The auto-migration is internal to v43; the on-disk config does not need to change.

## Phase 2 cutover diff (revised down)

The Phase 2 single PR to `homelab-infra` is smaller than originally planned:

1. **`services/renovate/docker-compose.yml` line 14:** `image: renovate/renovate:42.92` → `image: renovate/renovate@sha256:<digest resolved Day 8>`
2. **`services/renovate/systemd/renovate.service` line 11:** remove `ExecStartPre=/usr/bin/docker compose pull --quiet renovate` (image is now SHA-pinned)
3. **`services/renovate/config/config.json`:** Add a `customManager` block that watches the docker-compose `image:` line for new digests and opens reviewable PRs with `minimumReleaseAge: "14 days"` and `automerge: false`.
4. **No config field edits needed.** Optionally bundle: rename the 3 `fileMatch` → `managerFilePatterns` in customManagers for forward clarity.

## Recommended follow-up (post-cutover, low priority)

These are pure hygiene; v43 handles them all internally:

1. **Sweep PR series renaming `fileMatch` → `managerFilePatterns` across 13 repos.** Eliminates the `WARN: Config migration necessary` from logs. ~5 min per repo, batched via `cleanup-backlog-scout`.
2. **`Unify` `matchSeverity` placement update.** Single repo, single edit.
3. **Add explicit `renovate.json` to the 6 CI-020 gap repos.** Separate workstream (covered by improvement plan CI-020 enforcement).
