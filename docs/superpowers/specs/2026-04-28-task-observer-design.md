## Problem

The skills library grows through manual effort and stays frozen between deliberate review
sessions. There is no mechanism to capture patterns, corrections, and workflow gaps that
emerge naturally during work and translate them into skill improvements automatically.
The upstream `one-skill-to-rule-them-all` skill by Eoghan Henn (rebelytics) solves this
with a background observer that logs improvement opportunities and applies them on a
scheduled review cycle.

The skill is designed for Claude Cowork's shared folder model and is explicitly marked
untested for Claude Code without the desktop app. This design adapts it for the local
Claude Code environment with three targeted patches and purpose-built supporting
infrastructure.

## Decisions

- **Approach:** Thin adaptation of upstream SKILL.md, not a fork or reimplementation.
  The upstream contains three months of refinement; preserving that is worth the cost
  of maintaining three sed-based patches.
- **Source tracking:** Upstream repo as a git submodule at `.submodules/one-skill-to-rule-them-all/`.
  A patch script transforms it to `~/.claude/skills/task-observer/SKILL.md` on install
  and on each upstream update.
- **Observation storage:** Gitignored directories inside the repo
  (`skill-observations/`, `skill-updates/`), not in `~/.claude/` outside the repo and
  not committed to git history.
- **Activation:** Dual-layer -- CLAUDE.md structural trigger (compaction-resilient) plus
  SessionStart hook (manifest generation). Both layers are required; each covers a failure
  mode the other does not.
- **Skill discovery:** A manifest file at `skill-observations/available-skills.md`
  generated by the SessionStart hook replaces the Cowork-specific `<available_skills>`
  system prompt injection.
- **Review cadence:** Scheduled autonomous review Monday/Wednesday/Friday mornings via
  `CronCreate`, matching upstream author's recommended cadence. No manual-only fallback.
- **Update acceptance:** Staged updates in `skill-updates/YYYY-MM-DD/<skill-name>/SKILL.md`
  are accepted by copying to `~/.claude/skills/<skill-name>/SKILL.md`. No additional
  tooling required.

The patch script is the bridge between the two halves. The repo tracks the source
(submodule) and the transformation logic (patch script). The live skill is a build
artifact -- regenerated from those two inputs on install and on upstream updates.

**Upstream update workflow:**

```bash
git submodule update --remote .submodules/one-skill-to-rule-them-all
./scripts/apply-task-observer-patches.sh
```

## Section 2: The Three Patches

`scripts/apply-task-observer-patches.sh` applies exactly three transformations to the
upstream SKILL.md via `sed` before writing to `~/.claude/skills/task-observer/SKILL.md`:

1. **Shared folder path substitution** -- Replace every occurrence of
   `[your shared folder]` with the absolute repo path
   `/home/byron/dev/.claude`. This covers all log, archive, and staging paths
   referenced in the skill.

2. **Available skills redirect** -- Replace the `<available_skills>` reference with
   the manifest file path `/home/byron/dev/.claude/skill-observations/available-skills.md`.
   The CLAUDE.md activation section also documents this substitution so the observer
   knows where to look.

3. **Handoff doc section removal** -- Strip the "Without Persistent Storage" section
   (handoff doc mode). Claude Code always has filesystem access; that section adds token
   cost with no behavioural payoff in this environment.

The patch script is documented inline with the reason for each transformation so the
divergence from upstream is always legible.

**Attribution preservation:** The upstream SKILL.md contains a CC BY 4.0 attribution
block crediting Eoghan Henn (rebelytics.com). None of the three patches touch this block.
It passes through verbatim to the installed skill. This is a licence requirement, not
optional.

## Section 3: Activation

Two layers work together. Neither alone is sufficient.

**Layer 1: CLAUDE.md structural trigger (compaction-resilient)**

A new "Task observation" section added to `CLAUDE.md` (tracked in git, symlinked to
`~/.claude/CLAUDE.md`). This fires at true session start and again after context
compaction -- CLAUDE.md is re-read on resumption, so the observer re-invokes
automatically without any explicit action:

```markdown
## Task observation

At the start of any task-oriented session -- any interaction where you will
use tools and produce deliverables -- invoke the task-observer skill before
beginning work.

When loading any skill, check the observation log for OPEN observations
tagged to that skill at /home/byron/dev/.claude/skill-observations/log.md.
Apply their insights to the current work before beginning.

Available skills are listed in
/home/byron/dev/.claude/skill-observations/available-skills.md
(regenerated each session start). Use this file when the task-observer
skill references <available_skills>.
```

**Layer 2: SessionStart hook (manifest generation)**

`scripts/generate-skills-manifest.sh` added to `settings.json` SessionStart hooks
alongside the existing `keyword-tool-trigger.sh --reset` and
`run-superpowers-session-start.sh` entries. It runs before CLAUDE.md is processed,
so the manifest is ready when the observer needs it.

The script:
1. Creates `skill-observations/` in the repo if it does not yet exist
2. Walks `~/.claude/skills/` and writes a formatted skill inventory to
   `skill-observations/available-skills.md`
3. Extracts each skill's `description:` from its SKILL.md frontmatter for context
4. Handles both directory-based skills (containing `SKILL.md`) and flat `.md` skill files

The hook produces no output on success and is silent in normal operation.

## Section 4: Scheduled Review

A `CronCreate`-based scheduled remote agent runs Monday, Wednesday, and Friday mornings.
Set up during implementation using the `schedule` skill.

**Agent responsibilities per run:**

1. Read `skill-observations/log.md`, extract all `OPEN` observations
2. Read `skill-observations/cross-cutting-principles.md`
3. For each affected skill, integrate non-escalated observations -- additive changes,
   wording clarifications, edge case additions, factual corrections
4. Write updated SKILL.md to `skill-updates/YYYY-MM-DD/<skill-name>/SKILL.md`
5. Mark applied observations `ACTIONED` in the log
6. Write today's date to `skill-observations/last-review-date.txt`
7. Produce a brief summary of what was applied and what was escalated

**Escalation policy -- flagged but not applied autonomously:**

- New skill candidates (naming and scope require user input)
- Observations that remove or restructure existing content
- Observations flagged with uncertainty phrases ("not sure if...", "might be...")
- Conflicting observations pointing in opposite directions

**Agent model:** Sonnet 4.6 (standard skill-editing work, no deep reasoning required).

**Update acceptance:** Copy `skill-updates/YYYY-MM-DD/<skill-name>/SKILL.md` to
`~/.claude/skills/<skill-name>/SKILL.md`. No other steps.

**Staging cleanup (Keep-Two Rule):** The scheduled agent retains only the two most recent
date directories in `skill-updates/` and deletes older ones at the end of each run. This
prevents unbounded accumulation of staged files that were never accepted.

## Section 5: What Is Not Changed

The following upstream SKILL.md sections are adopted verbatim with no adaptation:

- Observation format (Issue, Suggested improvement, Principle fields)
- Numbering collision prevention (pre-write grep, write-time assertion, post-write verification)
- Confidentiality safeguards (five-layer open-source/internal boundary)
- Cross-cutting principles propagation (mandatory checklist on skill creation/regeneration)
- Surfacing protocol (silent during sessions, surface on session wrap or explicit request)
- Comprehensive review steps 0-8 (applied by the scheduled agent)
- Observation log management and archival logic
- Self-enforcement pre-flight checks

These sections represent the upstream's three months of refinement and are the primary
reason for the thin-adaptation approach over a reimplementation.
